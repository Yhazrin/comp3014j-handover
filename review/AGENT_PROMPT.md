# 给 Pro / coding agent 的任务

仓库：https://github.com/Yhazrin/comp3014j-handover （从当前 main 开始）。

请作为 COMP3014J 三人组的独立算法评审兼实现者。你的目标是争取私有算法档 A−（S≥127）并挑战 A（S≥131），不是把某个公开分数写好看。

1. 阅读 course/REQUIREMENTS.md、两份原始作业文档、course/benchmark/README.md、review/STATUS.md 和当前报告。以 submission/algorithm.py 的 VASH-Q 为基线。先按根 README 在 Python 3.11 复现 starter 84.93、A3 100、Q 126.45；核对哈希和评分聚合方式。若环境不支持运行，指出缺什么，不编造结果。
2. 对照实际源码，审查观测时序、切换状态机、七项 KPI 和运行限制。先找出一项有证据、能通过合法实时观测改善的损失，再提出至少两种不同机制，选一个适合三人解释和维护的方案实现。特别区分“提前预报一次请求”和“避免一次净中断”。避免重复 STATUS 中未能泛化的阈值微调。
3. 在新分支的 candidates/ 下工作，不直接改基线、评测器、A3 或课程数据。开发与验证分开；公开 1–6 已用于开发，7–10 也看过。先声明接受条件、种子和停止条件，再冻结代码哈希。用官方十场景和一套此前未用于选择的合成场景把候选与 Q 和 A3 同场比较，使用 tools/compare_transfer.py；一旦看过一套结果，就不再称其为盲测。未来信息只能用于明确标注的离线诊断。
4. 交付评审发现、候选代码或补丁、精确命令、输入/哈希、基线与候选的 S 和七项 KPI、逐场景退化、一个能隔离关键机制的消融及运行代价。只有证据支持时才推荐替换基线并同步报告；否则保留 Q，解释哪个假设被实验否定。区分公开结果、合成结果、私有档位。不得虚构成绩、学号、个人贡献或提交记录。
